# Jev MAGI

[中文](README.md) | English

Three personas each vote yes or no on the same proposal; two yes votes carry it. The judgments come from [TypeSafe Jev](https://docs.typesafe.ai/primitives/noul), and the interface is in Traditional Chinese.

![MAGI screenshot](docs/screenshot.jpg)

- **MELCHIOR · Reason**: Is it sensible and feasible?
- **BALTHASAR · Care**: Is it good for people and the future?
- **CASPER · Self**: Is this what you want?

The three judgments are independent. Input that cannot be answered with yes or no, such as an either-or choice or an open question, shows 錯誤 (error) in all three units.

## Download

Download the package for your platform from the [Releases](https://github.com/vanawaker/jev-magi/releases) page:

| Platform | File |
| --- | --- |
| macOS (Apple silicon and Intel) | `.dmg` |
| Windows | `.exe` |
| Linux | `.AppImage` |
| Android | `.apk` |

Open the app, press 開始議決 (start), and enter your [TypeSafe API key](https://console.typesafe.ai/keys). The key is stored on the device: in the Keychain on macOS, Credential Manager on Windows, the system keyring on Linux (without a keyring service it lasts for the current session only), and app-private storage on Android. It is only used to send requests to TypeSafe.

Packages are built automatically by GitHub Actions. **Only the macOS build has been tested; the Windows, Linux and Android builds are untested and may have problems.**

On first launch you may see a system prompt:

- **macOS**: if the developer cannot be verified, go to System Settings → Privacy & Security and click Open Anyway.
- **Windows**: if "Windows protected your PC" appears, click More info, then Run anyway.
- **Android**: allow installing apps from unknown sources in system settings.

## Run from source

For those who prefer to host it themselves. Requires Node.js 22.18 or later and a [TypeSafe API key](https://console.typesafe.ai/keys).

```sh
git clone https://github.com/vanawaker/jev-magi.git
cd jev-magi
npm install
npm start
```

Open <http://127.0.0.1:3000>, press 開始議決 (start), and enter your key when asked.

## Two ways to provide a key when running from source

- **On the page**: the key stays in the page's memory only and is cleared on reload.
- **In a config file**: copy `.env.example` to `.env`, set `TYPESAFE_API_KEY`, and run `npm start` again. The page then works without asking for a key.

If both are present, the key entered on the page is used. Proposals and keys are forwarded to TypeSafe through this server, which does not store them.

## Configuration

| Variable | Default | Description |
| --- | --- | --- |
| `TYPESAFE_API_KEY` | empty | Key used by the server; leave empty to enter one on the page |
| `HOST` | `127.0.0.1` | Listen address; use `0.0.0.0` to accept other devices on your network |
| `PORT` | `3000` | Listen port |
| `ALLOWED_HOSTS` | empty | Extra host names allowed to open the page, comma separated; `localhost` and `127.0.0.1` are always allowed |

To open the page through a LAN IP or a domain, add that IP or domain to `ALLOWED_HOSTS`. Behind a reverse proxy, keep the original `Host` header.

> **Note**: when `TYPESAFE_API_KEY` is set, anyone who can open the page spends that key's credits. For a public deployment, leave it unset and let each visitor enter their own key.
